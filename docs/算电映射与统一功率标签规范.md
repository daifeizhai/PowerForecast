# 算电映射与统一功率标签规范

> **版本**：v1.1（通用数据集接入版）  
> **适用范围**：PowerForecast 及后续新增的电力、算力、设备、任务和环境数据集。  
> **目标**：在**缺少设施总有功功率（kW）**时，充分利用现有数据，选择可解释的映射路径，尽可能构造设施功率估算序列；同时严格区分实测真值与估算结果。

## 1. 统一目标与基本约束

| 项目 | 统一规定 |
|---|---|
| 最终应用预测对象 | **整个数据中心的总有功功率**（facility active power） |
| 统一目标单位 | **kW**；电量使用 **kWh**，不能混用 |
| 统一时间粒度 | **15 分钟区间平均功率**；每天 96 点（不考虑夏令时变更的协议） |
| 核心预测任务 | **4 小时（16点）、24 小时（96点）、3 天（288点）、7 天（672点）** |
| 次优先预测任务 | 8 小时（32点） |
| 默认历史长度 | 14 天（1344点）；具体数据不满足时明确另设实验协议 |
| 核心评价指标 | **MAPE**；辅助 WAPE、MAE、RMSE |
| 核心方法思想 | **先分析算电关系 → 再构建映射或预测特征 → 最后深化机理** |
| 核心科学边界 | **可换算 ≠ 已实测；可估算 ≠ 已验证；只有输入、没有功率标签时，无法凭空“监督拟合”真实功率函数** |

## 2. 数据集接入：先做字段盘点，再自动选映射路线

### 2.1 字段分类与作用

| 已有数据 | 典型字段 | 能提供什么 | 映射时的注意事项 |
|---|---|---|---|
| 设施级电表 | 总有功功率、区间电量 | 总功率标签 | 核对表计覆盖范围、时间戳与单位 |
| 分项电表 | IT、制冷、照明、供配电等功率 | 分项合成设施功率 | 确认覆盖完整、口径互不重叠 |
| IT / 服务器电表 | IT总功率、单机/机架功率 | IT功率及合计 | 注意未计量设备与供配电边界 |
| 硬件清单 | GPU/CPU型号、数量、机器配置 | 估算设备能力和基准功率 | **型号或TDP不等于实际功率** |
| 设备运行状态 | GPU/CPU利用率、活动数、频率、显存等 | 设备动态功耗的解释变量 | 样本时间粒度、观测时点需核对 |
| 任务与调度日志 | 启停时间、并发数、任务类型、资源申请量 | 重建计算活动强度 | 申请资源、实际使用、实际功率各不相同 |
| 机房能效信息 | PUE、IT与辅助能耗占比 | IT→设施的近似映射 | **年/周期PUE不能直接当作15分钟真实倍率** |
| 环境与制冷 | 温湿度、冷机状态、制冷功率 | 建立辅助负荷模型 | 历史实测与未来可用预报必须区分 |
| 电参量 | 电压、电流、功率因数、电量 | 在条件充分时换算有功功率 | 仅有电流或视在功率不能直接视为kW |

### 2.2 依据可用数据选择映射路径

| 路径 | 已有数据条件 | 建议处理 | 输出身份 | 适用程度 |
|---|---|---|---|---|
| **A 直接采用** | 设施总表有功功率（kW/W） | 标准化单位、时间轴 | **实测总功率** | 最优先 |
| **B 电量换算** | 设施分区间电量（kWh/Wh）及区间长度 | 区间电量 ÷ 时间 | **由实测电量换算的区间平均总功率** | 高 |
| **C 分项求和** | 完整且不重叠的设施分项功率 | IT+制冷+其他设施负荷 | **分项派生总功率** | 较高；取决于覆盖度 |
| **D IT→设施** | 完整IT功率 + 适用的PUE或辅助负荷模型 | IT×PUE，或IT+辅助模型 | **估算设施总功率** | 需验证PUE时变性 |
| **E 设备→IT→设施** | 设备数量 + 分设备实测功率/可靠功耗曲线 | 合计IT功率，再走D | **估算设施总功率** | 需核对设备覆盖度 |
| **F 利用率→设备→设施** | 型号、数量、利用率/状态 + 功耗参数 | 设备功耗曲线→IT→设施 | **模型估算总功率** | 依赖标定数据质量 |
| **G 任务→资源→设施** | 任务日志、调度信息 + 资源映射 + 硬件及能效假设 | 推断资源活跃度→设备功率→IT→设施 | **情景/模拟总功率** | 探索性；不作实测验证 |
| **H 条件不足** | 仅型号、仅利用率、仅PUE、仅任务类别等 | 记录缺项，保留原始任务，不强制映射 | **暂无可信总功率标签** | 不可宣称设施负荷预测 |

> **选择原则**：优先使用信息最直接、假设最少的路径。路径 C—G 若有未覆盖负荷，必须明确计入残差模型或缺口，不能将不完整的 IT 功率直接命名为“总功率”。

## 3. 通用映射公式与使用边界

| 适用条件 | 公式或方法 | 关键约束 |
|---|---|---|
| 区间电量已知 | \(\overline P_{\mathrm{facility}}(t)=E_{\mathrm{facility}}(t)/\Delta t\) | E单位kWh，\(\Delta t\)单位h；15分钟取0.25h |
| 完整分项功率已知 | \(P_{\mathrm{facility}}=P_{\mathrm{IT}}+P_{\mathrm{cooling}}+P_{\mathrm{other}}\) | 分项范围完整、不重复，统一为同一时段区间均值 |
| 设备功率曲线可建 | \(\hat P_i(t)=P_{i,\mathrm{idle}}+[P_{i,\mathrm{load}}-P_{i,\mathrm{idle}}]g_i(u_i(t))\) | \(g_i\)优先用成对实测标定；线性\(g_i(u)=u\)只作为基线假设 |
| IT边界完整 | \(\hat P_{\mathrm{IT}}(t)=\sum_i\hat P_{\mathrm{equipment},i}(t)\) | 服务器/CPU/GPU/网络/存储按选定边界覆盖，不重复计数 |
| 已有辅助负荷模型 | \(\hat P_{\mathrm{facility}}=\hat P_{\mathrm{IT}}+\hat P_{\mathrm{aux}}\) | 辅助功率需含制冷与其他设施负荷，标明拟合来源 |
| 仅有IT与PUE | \(\hat P_{\mathrm{facility}}(t)=\hat P_{\mathrm{IT}}(t)\times\mathrm{PUE}_{\mathrm{assumed}}\) | **情景近似**；PUE通常以一段期间的能耗比定义 |
| 有配对实测数据 | \(\hat P_{\mathrm{facility}}=f_\theta(\text{任务、利用率、设备、环境等})\) | 使用训练段拟合；验证段选参；测试段仅评价 |

**两条重要规则**：① 只知道设备额定功率/TDP，不能认为设备始终按该功率运行；② 采用整机功率模型时，不能再叠加该整机内部CPU/GPU功率。

### 3.1 “拟合”和“估算”必须区分

| 情况 | 可以做什么 | 不能声称什么 |
|---|---|---|
| 有同步的**输入—实测功率配对样本** | 监督回归、功耗曲线校准、跨站迁移检验 | 未经外部测试就已普适 |
| 没有本数据集功率，但有**同类设备外部标定曲线** | 迁移功耗曲线并做偏差/敏感性分析 | 本站总功率已被实测验证 |
| 仅有**硬件规格和经验PUE** | 建立物理启发式或边界情景估算 | 该估算等同于实际总表标签 |
| 仅有作业与资源日志，缺少设备数量/功耗/站点范围 | 做资源画像、相对活动强度预测，列出补数清单 | 已可靠恢复设施总功率（kW） |

## 4. 通用实施步骤（适用于未来所有新数据集）

| 步骤 | 执行动作 | 最低可检查产物 |
|---|---|---|
| **1. 数据审计** | 明确时间跨度、采样粒度、物理单位、设备/场站边界、缺失率、已有字段 | `dataset_profile` |
| **2. 路径选择** | 按第2节选择 A—H，列出必要假设与缺项 | `mapping_strategy` |
| **3. 时间对齐** | 明确功率瞬时值还是区间均值、任务生命周期、各字段可用时点；转换为15分钟网格 | `time_semantics`、质量报告 |
| **4. 建立映射** | 先用低复杂度、可解释的公式；有配对功率后再训练回归/非线性模型 | `mapping_version`、参数表 |
| **5. 可靠性检查** | 比较实测与估算（如可用）；否则给出参数区间和情景敏感性 | `validation_status`、误差/敏感性表 |
| **6. 进入预测** | 使用既有统一模型接口，保留目标来源身份与任务协议 | 带标签来源的预测序列 |
| **7. 分层评价** | 映射误差、预测误差分开统计；标明评价基准是否实测 | 独立评价表、复现记录 |

## 5. 映射效果、预测精度和泛化评价

| 评价内容 | 对比对象 | 优先指标 | 使用边界 |
|---|---|---|---|
| **功率映射误差** | 映射功率 vs 独立实测总功率 | MAPE、WAPE、MAE/RMSE | 仅在有同步实测真值时计算 |
| **真实负荷预测误差** | 预测总功率 vs 未来**实测总功率** | **MAPE优先** | 正式95%目标需在此类评价中论证 |
| **估算情景预测误差** | 预测功率 vs 未来**映射估算序列** | MAPE、WAPE、MAE/RMSE | 仅衡量对估算序列的预测效果 |
| **跨数据集泛化** | 新数据集/新场站的独立测试结果 | MAPE变化、重新校准时间 | 对齐标签性质后比较；记录迁移代价 |
| **映射敏感性** | 改变功耗参数、设备覆盖和PUE假设 | 估算范围、相对变化率 | 无真值时也应报告；不能冒充实测误差 |

| MAPE约束 | 统一处理 |
|---|---|
| 定义 | \(\mathrm{MAPE}=\frac{100\%}{n}\sum_{t\in\mathcal V}|(y_t-\hat y_t)/y_t|\) |
| 零值/近零值 | **测试前固定**有效值阈值；同时报告被排除点数，不隐藏低负荷困难时段 |
| 模型选择 | 优先依据验证集MAPE；独立测试前冻结模型、参数和映射规则 |
| 精度目标 | **95%对应实测总功率MAPE≤5%**（当前研究目标，不是已达到的结果）；96%口径待确认 |
| 不允许 | 估算标签上的低MAPE、利用率上的低MAPE，冒充实测设施总功率达标 |

## 6. 因果性与数据质量约束

| 风险 | 必须执行的规则 |
|---|---|
| 未来信息泄漏 | 任一起报点只能使用**当时已知或已观测**信息；不可使用未来真实利用率/天气/总功率 |
| 生命周期统计 | 若某字段是任务结束后才计算的**全生命周期均值**，只能用于离线事后分析，不能冒充此前时刻的在线测量 |
| 任务时间聚合 | 可利用任务启停事件估计15分钟活跃数量；若精确未来结束时刻未知，不能作为提前预测的已知特征 |
| 伪时间精度 | 只有小时级/生命周期均值时，不得插值后宣称拥有真实15分钟功耗变化 |
| PUE适配 | 记录PUE的统计周期、适用范围和来源；不得把全年平均PUE直接解释为各15分钟的实际PUE |
| 未覆盖设备 | 记录设备数量、工作/待机状态、覆盖率和未计量部分；条件不足时标注不可识别缺口 |
| 训练与测试 | 功耗映射参数的拟合、时间序列预测模型的选择均不得使用独立测试标签 |
| 功率边界 | 区分“GPU芯片功率”“服务器输入功率”“IT总功率”“设施总功率”，层级不允许跳用 |

## 7. 统一输出接口与元数据

### 7.1 标准化序列

| 字段 | 含义 | 示例/约束 |
|---|---|---|
| `dataset_id` / `site_id` | 数据集、场站/集群身份 | 不同站点不可直接混作一条时序 |
| `timestamp` | 时间戳及所在时区 | 明确区间起点/终点 |
| `interval_minutes` | 数据窗口长度 | 默认15 |
| `target_kw` | 区间平均功率 | **仅当物理映射条件充分时生成** |
| `target_scope` | 电力计量覆盖边界 | `facility` / `it` / `server` 等 |
| `label_origin` | 标签来源 | `measured` / `energy_converted` / `component_sum` / `calibrated_estimate` / `assumed_scenario` |
| `mapping_route` | 采用的映射方案 | A—H |
| `coverage` | 设备/负荷覆盖说明 | 明确已覆盖与未知边界，不伪造比例 |
| `mapping_version` | 公式、参数与代码版本 | 可追溯、不可覆盖历史实验 |
| `parameter_sources` | 硬件参数、外部标定、PUE来源 | 明确文献/设备资料/实测 |
| `validation_status` | 是否使用独立实测验证 | `validated` / `unvalidated` / `not_applicable` |
| `assumptions` | 缺项处理和理论假设 | 允许为空但不能隐去实际假设 |

### 7.2 数据质量与路线准入

| 检查项 | 通过标准 |
|---|---|
| 单位 | W、kW、Wh、kWh明确，电量须按对应区间换成平均功率 |
| 边界 | 明确设施/IT/设备层级；不存在重复计数 |
| 时间 | 区间、时区、采样粒度与可用时点一致 |
| 参数 | 每项关键功耗参数、PUE均可追溯来源或标明未知 |
| 可评价性 | 有实测标签才能验证真实总功率映射/预测精度 |
| 不足数据 | 允许输出 `not_estimable` 和缺失字段清单，不生成虚假的kW真值 |

## 8. 与现有PowerForecast项目衔接

| 模块 | 处理方式 |
|---|---|
| `configs/datasets/` | 每个数据集独立维护字段/单位/时区/映射方案/参数来源 |
| `src/data/` | 扩展通用功率标签适配和映射层，不把数据集名写死在算法中 |
| 统一预测接口 | 尽量复用现有 `ForecastInputs`、`WindowBatch`、MAPE评分与归档流程 |
| 实验协议 | 保留既有 Google D14/D22 与 NLR 历史协议；新增数据集独立声明训练/验证/测试划分 |
| 实验报告 | 严格区分真实标签、派生标签和估算情景；映射精度与预测精度分开呈现 |
| 当前优先级 | 优先完善4小时、24小时、3天、7天；机理驱动的特征增量须用验证集检验 |

**一句话约束**：**新增数据集若无kW总功率，优先尝试“电量换算 → 分项合成 → IT与PUE映射 → 设备功耗映射 → 任务资源情景估算”；有配对实测数据才做监督拟合与真实精度验证，缺少必要条件时宁可标明不可估算，也不能伪造总功率真值。**
